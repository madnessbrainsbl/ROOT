What is bundled

The v0.1.0 repository includes 250 recently added entries from the CISA Known Exploited Vulnerabilities catalog. Records are enriched from the public CVE List V5 when a published CNA record is available. The result is deliberately small enough to review, clone, and use offline.

The catalog is not a live threat-intelligence feed, a complete CVE mirror, or a replacement for vendor advisories. It is a reproducible learning and research dataset that supports filters, pagination, individual records, and an in-browser SQL workflow.

Traceable generation

The standard-library generator in scripts/build_cve_seed.py fetches the official CISA KEV data and matching CVE List V5 records, normalises the fields used by RØOT, and writes the JSON seed. A separate provenance document records the generation time, source URLs, record count, and SHA-256 digest.

python scripts/build_cve_seed.py --limit 250
python serve.py

Generation is a maintainer action. The application never downloads vulnerability data on startup, accepts no API token, and exposes no update endpoint.

Read-only API

GET /api/cves/status
GET /api/cves?severity=CRITICAL&q=apache&limit=50&offset=0
GET /api/cves/counts
GET /api/cves/CVE-2025-0001

Query values are parameterized before reaching SQLite. Pagination, severity values, search length, and CVE identifiers are validated at the HTTP boundary. POST requests under /api/ are rejected.

Operational rule: confirm important vulnerability details against the CVE record, CISA entry, and vendor advisory before making a security decision.

Static and self-hosted modes

On the self-hosted Python server, the JSON seed is imported into SQLite and queried through the REST API. On GitHub Pages, the browser falls back to the same tracked JSON seed and performs filtering locally. Both paths use the same public source data.
