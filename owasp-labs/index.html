Why an offline training range?

Reading a vulnerability description rarely builds the judgement needed to recognise the same failure in unfamiliar code. Cloud training platforms solve part of that problem, but they can require accounts, subscriptions, network access, or a running vulnerable service. RØOT takes a smaller approach: the exercises are deterministic browser simulations designed to demonstrate the security decision without exposing a real target.

This makes the range suitable for individual study, classroom demonstrations, interview preparation, and private environments where training data cannot leave the network. Progress, quiz answers, flags, and notes remain in the browser.

Web Top 10 workflow

Each Web category uses the same repeatable flow. The theory view explains the trust-boundary failure and maps it to relevant CWE identifiers. The practice view presents controlled challenges. The remediation view puts vulnerable and safer implementations side by side. A bilingual quiz checks whether the underlying rule is understood rather than memorised.

  • Broken Access Control and IDOR scenarios
  • Cryptographic and authentication failures
  • Injection, XSS, SSRF, and unsafe deserialisation patterns
  • Security misconfiguration and vulnerable-component decisions
  • Logging, integrity, and exceptional-condition handling

API Security mini-labs

The API track focuses on object- and function-level authorization, resource consumption, unsafe business flows, server-side request forgery, inventory management, and untrusted third-party APIs. Request and response simulations make the data flow visible while keeping the exercise isolated from external systems.

Safety boundary: RØOT teaches techniques for systems you own or are explicitly authorized to test. It is not an automated scanner and does not attack remote targets.
