Where RØOT fits

RØOT is designed for instructors, mentors, and study groups that need a predictable demonstration environment. It can run from a laptop, a classroom server, or Docker on an internal network. Because the included exercises are browser simulations, students can focus on the security concept instead of spending the lesson troubleshooting vulnerable infrastructure.

The platform is not a learning-management system. It does not collect student identities, provide remote code execution, or replace a realistic development environment. It is best used for explanation, guided practice, discussion, and assessment before moving to a dedicated vulnerable application.

A 90-minute session

  1. 15 minutes: introduce the trust boundary and relevant OWASP category.
  2. 20 minutes: inspect a vulnerable flow and predict the failure.
  3. 25 minutes: complete two controlled challenges and compare approaches.
  4. 15 minutes: review vulnerable and remediated code side by side.
  5. 10 minutes: complete a quiz and discuss incorrect answers.
  6. 5 minutes: export progress or assign a follow-up investigation.

Suitable learning outcomes

  • Explain why authentication is not the same as authorization.
  • Recognise missing object- and function-level access checks.
  • Trace untrusted input into interpreters and outbound requests.
  • Distinguish superficial filtering from structural remediation.
  • Use CWE, CVE, and vendor sources without treating severity as the entire risk model.

Deployment

docker compose up --build
# learners open http://instructor-host:8080/app/

For a single machine, python serve.py binds to loopback by default. Network exposure must be explicit through ROOT_HOST or the Docker configuration.

Privacy: progress is stored in each browser. RØOT has no analytics and sends no classroom activity to the project maintainer.

Feedback for an education pilot

A useful pilot reports the learner level, chosen module, time available, confusing instructions, and whether the remediation explanation changed the learner's proposed fix. Open a GitHub issue without including student names, target data, credentials, or confidential findings.
