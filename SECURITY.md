# Security policy

## Supported version

Security fixes are provided for the latest tagged release.

## Reporting a vulnerability

Do not publish an exploitable issue before the maintainer has had a reasonable
chance to investigate it. Send a private report through GitHub's **Report a
vulnerability** form when available. If private reporting is unavailable, open
an issue that contains only a non-sensitive summary and ask for a private
contact channel.

Include the affected version, reproduction steps, impact, and a minimal proof
of concept. Never include real credentials, personal data, or unauthorized
target data.

RØOT's bundled lab behavior is intentionally vulnerable and is not itself a
security report unless it escapes the local simulation boundary.
